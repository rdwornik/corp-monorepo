# ADR-31: Retire single-file HANDOFF (docs/HANDOFF.md + scripts/update_handoff.py)

- **Status:** Accepted
- **Date:** 2026-05-18
- **Related:** ADR-42 (handoff format v3, `.dev-knowledge/docs/decisions/`), ADR-36 (audit-tool / read-only target-repo contract, `.dev-knowledge/docs/decisions/`), ADR-41 (BACKLOG.md, `.dev-knowledge/docs/decisions/`), ADR-30 (companion: retire CHANGELOG.md)
- **Decommission:** `docs/HANDOFF.md`; `scripts/update_handoff.py`; the legacy session-handoff prescription in `CLAUDE.md` §"Session Handoff" (rewritten to point at the `.dev-knowledge` ADR-42 convention)
- **Source:** 2026-05-18 universalization-review audit §2.7, §2.13 (`docs/audits/2026-05-18-universalization-review.md`); rollout branch `docs/handoff-retirement`

## Context

The master-file handoff pattern in corp-monorepo predates the ecosystem
handoff spec. The going-forward convention is folder-per-session bundles
generated and stored in `.dev-knowledge`
(ADR-42 + `.dev-knowledge/protocols/HANDOFF_PROCESS.md`), NEVER written
into target repos (ADR-36 read-only contract).

`docs/HANDOFF.md` was ~7 weeks stale at retirement time: last
content-bearing commit 2026-03-29; rename-only commit 2026-03-30; the
regenerator only refreshed counts/timestamps, not content structure.
Many references inside the file pointed at `.ecosystem/` paths removed
2026-03-30 and at `decisions/` instead of `docs/decisions/`.

The only load-bearing content was §"Open Decisions" + §"Pending Fixes" —
both rehomed to `BACKLOG.md` (created same day) before deletion. All
other sections were stale dated snapshots or duplicates of authoritative
content elsewhere (`CLAUDE.md`, `ARCHITECTURE.md`, `docs/decisions/`,
CLI help) and are preserved in git history.

## Decision

Retire the corp-monorepo-local single-file handoff mechanism:

- Delete `docs/HANDOFF.md` (456 lines, "Corporate OS — Master Session
  Handoff", regenerated by the script below). Last commit touching the
  file before removal: `d2d2fdf` (2026-03-30 rename from
  `MASTER_HANDOFF.md`).
- Delete `scripts/update_handoff.py` (the regenerator; sole consumer was
  `docs/HANDOFF.md`; no remaining call sites).
- Rewrite `CLAUDE.md` §"Session Handoff" to point at the ecosystem
  convention (no replacement mechanism inside this repo).

The ecosystem handoff flow in `.dev-knowledge` is the replacement:

- **Where bundles live:**
  `.dev-knowledge/docs/handoffs/{YYYY-MM-DD}-corp-monorepo-{type}/`
  (flat 11-file folder; type defaults to `session-sync`).
- **Trigger:** in Claude Code at `.dev-knowledge`, the operator says
  "Make handoff for corp-monorepo" (Stage 1) → pastes the OLD browser
  chat response into `stage2-response.md` → says "Complete handoff for
  corp-monorepo" (Stage 3).
- **Spec:** `.dev-knowledge/protocols/HANDOFF_PROCESS.md` (operational)
  + `.dev-knowledge/docs/decisions/ADR-42-handoff-format-v3.md`
  (authority).

## Consequences

### Positive
- corp-monorepo honors the ADR-36 read-only contract — no handoff
  artifacts are generated or stored inside the target repo.
- One canonical handoff workflow across the ecosystem (ADR-42).
- Eliminates a ~7-week-stale single-file with multiple known
  reference-drift defects (`.ecosystem/` paths, wrong directory names,
  self-contradicting counts).

### Negative
- The folder-per-session pattern requires the operator to be in
  `.dev-knowledge` (not in corp-monorepo) when generating handoffs.
  Documented in `CLAUDE.md` §"Session Handoff" so future agents know
  where to route.
- The frozen legacy file `docs/handoffs/2026-04-15-handoff.md` was
  left in place by this rollout step but subsequently deleted in the
  post-audit cleanup (`chore: remove legacy docs/handoffs/ leftover`,
  same branch sequence). No longer in scope.
